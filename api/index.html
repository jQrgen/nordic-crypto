Nordic Crypto data API

A public JSON feed of the site, for apps and for other tools. No account and no API key. It is regenerated whenever the site is built.

Market prices

Nordic exchange prices are market data, not investment advice. /api/v1/markets.json lists each pair with symbol, base, quote, last, bid and ask when the exchange publishes them, the exchange id, name and country, fetched_at, the source URL, and volume when the exchange published it. volume_base is the base asset with no named window (Firi). volume_base_24h and volume_quote_24h are the last 24 hours (NBX). A missing volume is null, not zero. Quotes are NOK, SEK, DKK and EUR. One exchange is /api/v1/markets/{exchange}.json (firi, nbx, coinmotion). One asset is /api/v1/markets/by-asset/{symbol}.json. Venues without a public ticker are listed under skipped and are not given a made-up price.

/api/v1/markets/aggregated.json is one row per pair. BTC-NOK is not averaged with BTC-EUR. last is the arithmetic mean of published last prices. mid is the mean of (bid+ask)/2 and is not mixed into last. price equals last when any last exists, otherwise mid. min and max use that same series. There is no VWAP. Volume is summed only inside the same field and the same pair. logo_url is an SVG from cryptocurrency-icons (CC0 1.0) when that set includes the asset, served at /api/v1/markets/logos/{symbol}.svg, and null otherwise. The per-asset file repeats aggregated and the logo.

The build fetches the exchanges. .github/workflows/markets-refresh.yml rewrites the JSON on gh-pages about once an hour, including the aggregated file and the icons. The markets page reloads this file, and refreshes Firi and Coinmotion in the browser because those APIs send Access-Control-Allow-Origin: *. NBX does not, so those rows follow the file. The same document on the gh-pages branch: raw.githubusercontent.com/jQrgen/nordic-crypto/gh-pages/api/v1/markets.json.

curl -fsS https://nordiccrypto.no/api/v1/markets.json
curl -fsS https://nordiccrypto.no/api/v1/markets/aggregated.json

Talks

Public talks on bitcoin, cryptocurrencies and blockchain held in Norway, Sweden, Denmark, Finland, Iceland, the Faroe Islands, Greenland and Åland are at /api/v1/talks.json, newest first. One talk is /api/v1/talks/{id}.json. One country is /api/v1/talks/by-country/{country}.json (NO, SE, DK, FI, IS, FO, GL, AX). description is ours. title, dates, duration, channel and speakers come from the platform at source_url. A field the platform did not state is null. embed is true only when that platform's oEmbed response includes a player. The HTML page loads the player after a click: YouTube via youtube-nocookie.com, Vimeo via player.vimeo.com. event_id and calendar_event_id are the same event id when the talk is linked. That event is /api/v1/events/{id}.json (and /api/v1/events/previous.json when it is a past event) and the page is /calendar/{id}/. talk_ids on the event lists those talks. unlink_reason is set when the video page did not state a day or a place, and event_id is then null. speaker_ids are who's who ids in the same order as speakers. The person, at /api/v1/orgchart/{id}.json, lists those talks and any affiliation the talk page stated.

Several outlets, one story

A story keeps one primary outlet. Other outlets that covered the same event are in also_covered_by. sources lists the primary first, then the others. Each outlet has outlet, outlet_name, url, title (that outlet's headline), published, lang, country, source_type and logo. source_type is national, regional (regional and local), official (justice and official: police, prosecutors, courts, regulators) or international. coverage.count is the number of outlets. coverage.by_country and coverage.by_source_type are the counts and shares for the bars. Every source type is present, including a count of zero. html_url is our page for that story. url is the primary outlet. Kaupr stays a news source only.

Events

Upcoming and past events are in /api/v1/events.json. Luma calendars are taken from the public Subscribe iCal URL on each event source (ics). Luma city pages, category pages and the discover API are not used. An individual Luma event page is schema.org JSON-LD. Eventbrite organizers and venues are read with the v3 API when the server has EVENTBRITE_TOKEN. That token is not in this feed and is not committed. Without it, the event page JSON-LD is used. The same title, date and venue is one event. Finished events stay in the feed. description.text is the organiser's own wording, description.lang is the language of that text, and description.source_url is the page it came from. description.i18n holds a translation where we have one. The field is null when the source had no description. Predatory conference listings are not a source. Kaupr is never a sponsor.

Languages

English is the default field (summary, title, text). Translations that we have published sit in summary_i18n, title_i18n, subtitle_i18n, note_i18n, text_i18n and about_i18n, keyed by nn, nb, sv, da, fi and is. Other site languages use the English field until a translation is published. On a news item, title stays the source headline, title_en is our English headline and title_i18n is our headline in the Nordic site languages. The pages show the page-language headline first and the source headline underneath when they differ. Each outlet's own headline, inside sources, stays in that outlet's language. Dates are ISO 8601.

/api/v1/languages.json lists every site language with code, native_name, english_name, rtl, html_lang and home. /api/v1/geo-language.json is the country-to-language guess used on a first visit. The IP country comes from the tipworker GET /api/geo (Cloudflare request.cf.country). Nothing is stored. The nc_lang cookie, set by the language switcher, always wins.

Source logos

Each outlet in /api/v1/sources.json has logo_url (absolute PNG or WebP URL, never SVG, or null) and logo (kind, file_url (the original, SVG or WebP), raster_url (same as logo_url), source_url, author, license, license_url, credit, or null). Each news item has source_logo_url, so an app can show the outlet's logo next to the headline. Logos come from Wikimedia Commons (with the licence) or the publisher's own site. They are the publishers' trademarks, shown only to identify the source of a headline. A logo stays null until the editor has checked it.

CORS

GitHub Pages sends Access-Control-Allow-Origin: * on these files, so a page on another site can fetch() them. GitHub Pages does not apply a custom headers file. Use the .json file name; opening a directory does not return the JSON.

Editorial

The sign-off is The Nordic Crypto team. Kaupr (kaupr.io) is a news source only and is never a sponsor. Nothing here is investment advice.

Brand accounts

ios in /api/v1/meta.json is the public TestFlight invite for the Nordic Crypto iOS app. There is no App Store listing. apple_tv says the TestFlight version especially supports Apple TV. apple_tv_i18n has that short sentence in every site language. The brand name stays Nordic Crypto.

/api/v1/meta.json includes social for the iOS app. social.telegram is the Nordic Crypto chat at https://t.me/nordiccryptochat. social.x is the brand account at https://x.com/xcryptonordic (@xcryptonordic), also listed as urls.x. urls.telegram repeats the chat URL. urls.rss is the English story feed at /rss.xml. Each language home has its own rss.xml. urls.newsletter is the signup page on this site. label is the short name (Telegram, X). name is the English link text. name_i18n has nn, nb, sv, da, fi and is. Other site languages use name.

Browser notifications

When workers/push/public.json has a Worker URL, a button at the bottom of each page is Web Push. Until then the page says the service is not switched on and does not call a Worker. Subscriptions live on a Cloudflare Worker, not in this static feed. After a publish, GET /api/push/feed.json on that Worker lists the same batches (title, short summary, URL, country, and translations when we have them). One publish is one batch. The document says "apns": "not implemented": Apple Push Notification service is out of scope. An iOS app can poll the feed. The Worker URL is set when workers/push/ is deployed; it is not a path on this site. Subscriptions are not in the feed. This API's /api/v1/news.json remains the full published list.

Endpoints

MethodPathReturns
GET/api/v1/index.jsonDiscovery document: every endpoint, with example URLs.
GET/api/v1/news.jsonPublished news and our own stories, newest first.
GET/api/v1/news/by-country/{country}.jsonPublished news for one country code: NO, SE, DK, FI, IS, NORDIC or EU.
GET/api/v1/news/topics.jsonTopic ids present in the published news, with counts.
GET/api/v1/newsletters.jsonPublished newsletter issues, newest first. The list omits the HTML body; the issue URL includes text and html.
GET/api/v1/events.jsonPublic events, soonest start first, including past events.
GET/api/v1/events/upcoming.jsonEvents that have not ended, soonest first. Judged in the event's own offset.
GET/api/v1/events/past.jsonFinished public events, newest first. Finished events stay in the archive.
GET/api/v1/events/previous.jsonPrevious events, newest finish first. Finished calendar events plus backfilled public events (source backfill). Backfill is not on the calendar or in upcoming or past.
GET/api/v1/events/by-country/{country}.jsonPublic events for one country code.
GET/api/v1/talks.jsonPublic talks on bitcoin, cryptocurrencies and blockchain in the Nordic countries, newest first. A player is embedded on the site only when embed is true (YouTube via youtube-nocookie.com, or the Vimeo player). Unknown fields are null. description is ours; title and the other details come from the platform.
GET/api/v1/talks/by-country/{country}.jsonPublic talks for one country code: NO, SE, DK, FI, IS, FO (Faroe Islands), GL (Greenland) or AX (Åland).
GET/api/v1/sources.jsonNews outlets, justice-system press pages, the public search terms, and event sources. coverage is national, regional, local or justice. region is the place. feed is null when no working RSS, sitemap or index page was verified. method is rss, html, sitemap, search or manual. Event sources name the intake method. Luma calendars use a public iCal subscribe URL. Eventbrite organizers and venues use the v3 API when the server has EVENTBRITE_TOKEN; the token is not in this feed. Without it, event pages are schema.org JSON-LD. icon_url is a public icon from the outlet when one was easy to find. logo_source is the URL the stored logo was fetched from. logo is the checked outlet image for that source id when one is on file, used only to identify the source. Kaupr is marked as a news source only and is never an event sponsor.
GET/api/v1/academia.jsonEditor-approved courses, student groups, publications and research.
GET/api/v1/academia/courses.jsonAcademia section: courses.
GET/api/v1/academia/groups.jsonAcademia section: groups.
GET/api/v1/academia/publications.jsonAcademia section: publications.
GET/api/v1/academia/research.jsonAcademia section: research.
GET/api/v1/academia/{id}.jsonOne academia row. The id is in academia.json.
GET/api/v1/books.jsonPublished books on bitcoin, crypto and blockchain by Nordic authors or about the Nordic countries. title is the original title. authors are as printed; author_role is "editors" for an edited volume. language is a code (nn, nb, sv, da, fi, en). source is the library catalogue or publisher page where the row was checked. about is our one-line description in English. No cover images.
GET/api/v1/orgchart.jsonPublished who's who: organisations, people, relations, regulation notes and caveats. A person named on a talk has talk_ids, event_ids and talks. affiliations lists the organisation the talk page stated for that talk, with the talk date when the page gave one, the source URL and the retrieval time. An affiliation the page did not state is omitted.
GET/api/v1/orgchart/relations.jsonRelations between published who's who entries.
GET/api/v1/orgchart/regulation.jsonShort regulation status for each Nordic country, as on the who's who page.
GET/api/v1/orgchart/relations/{id}.jsonOne relation from the who's who.
GET/api/v1/profiles.jsonPublic profile links (Wikipedia, X, Wikidata and similar) for people and organisations.
GET/api/v1/images.jsonLogos and photos used on the public who's who, with licence and credit. These are not newspaper photographs.
GET/api/v1/illustrations.jsonPictures used on story cards and story pages. Each record has source, author, license and url. No photograph from another newspaper is included. Outlet logos are in images.json and on each news item as source_logo.
GET/api/v1/changelog.jsonSite changelog (product changes, not the news), newest first.
GET/api/v1/rules.jsonHow EU crypto rules become law in the five countries. Simplified, not legal advice. Omitted while the page is still a placeholder.
GET/api/v1/archive/articles.jsonAppend-only archive of stories that have been on the public site. removed is true when a story later left the site; the row stays.
GET/api/v1/markets.jsonNordic exchange prices. Market data, not investment advice. Each ticker names the exchange, fetched_at, the source URL and volume when the exchange published it. NOK, SEK, DKK and EUR only. aggregated is one row per pair.
GET/api/v1/markets/aggregated.jsonOne price per base-quote pair. BTC-NOK is separate from BTC-EUR. last is the mean of published last prices. mid is the mean of bid/ask midpoints and is not blended into last. Volume is summed only within the same field and the same pair. logo_url is a CC0 icon when cryptocurrency-icons includes the asset, otherwise null.
GET/api/v1/markets/{exchange}.jsonPrices from one included exchange: firi (Norway), nbx (Norway) or coinmotion (Finland).
GET/api/v1/markets/by-asset/{symbol}.jsonPrices for one asset (the base symbol, such as BTC) on every included Nordic exchange, plus aggregated pairs for each quote currency and logo_url when an icon is available.
GET/api/v1/languages.jsonSite UI languages: code, native name, English name, rtl, html lang and home URL.
GET/api/v1/geo-language.jsonCountry to default site language. An IP guess only; the nc_lang cookie from the language switcher wins.
GET/api/v1/meta.jsonSite name, languages, countries, page list, CORS, editorial notes and brand social accounts (social.telegram, social.x).

Not included

Drafts, the editor queue, rejected stories, reader tips, newsletter subscriber addresses, the analytics token, and private personal data are not in this feed. An unknown id is a normal site 404, not a JSON error.

Field names in version 1 stay. New fields may appear. A breaking change would use a new path.
